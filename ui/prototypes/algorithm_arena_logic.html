算法模块“竞技场”机制逻辑汇报

我们的核心预测引擎采用了一种“赛马机制（Model Arena）”。简单来说，对于每一个 SPU，我们不迷信单一算法，而是让多个模型“同台竞技”，谁在验证集上跑得最准，就选用谁来预测未来。

输入历史数据 → 🏃‍♂️ 多模型同时开跑 → 🎯 验证集PK误差 → 🏆 胜者全拿 (Winner Takes All)

一、 参赛选手 (The Models)

我们派出了风格迥异的四位选手，确保能应对不同类型的销售曲线：

选手名称 擅长领域 特点
Prophet (Facebook先知) 趋势与节假日 擅长捕捉长期增长/下降趋势，对春节、黑五等节假日效应非常敏感。
ARIMA (经典统计) 周期性波动 数学功底深厚，擅长捕捉数据的自相关性（如“这周销量跟上周有关”）。
XGBoost (机器学习) 非线性复杂特征 暴力美学，擅长从历史销量中挖掘出人眼看不出的复杂规律。
Ensemble (加权融合) 稳健保底 集众家之长，将上述模型的预测结果加权平均，通常最稳，不易大起大落。

二、 比赛规则 (The Rules)

为了公平起见，我们制定了严格的比赛流程：

第一步：切分赛道 (Train/Test Split) 我们将历史数据切分为两部分：
  • 训练集 (Training Set)：比如过去 3 年的数据，用来“训练”模型。
  • 验证集 (Validation Set)：最近 4~10 周的数据，用来“考试”。模型必须预测这段时间，并与真实发生的销量对比。
第二步：实战 PK (Backtesting) 所有模型在训练集上学习后，分别预测验证集那 4~10 周的销量。

裁判标准：WMAPE (加权平均绝对百分比误差)
公式通俗版：(预测值 - 真实值) 的总绝对差 ÷ 真实总销量
误差越小，得分越高。
第三步：选出冠军 (Selection) 系统自动比较各模型的 WMAPE：
  • 如果 Prophet 误差 15%，XGBoost 误差 8% → XGBoost 胜出。
  • 最终输出：仅采用冠军模型的预测结果作为该 SPU 未来的建议备货量。

三、 为什么这么做？ (Why This Works)

  • 因地制宜：有的品是季节性的（泳衣），有的品是爆发性的（网红款），单一模型无法通吃。竞技场机制保证了“每个品都用最适合它的模型”。
  • 自动进化：如果某个月市场风向变了（例如从线性增长变成周期波动），在下一次跑数时，擅长周期的 ARIMA 可能会击败 Prophet 成为新冠军，系统自动适应变化。
  • 防止过拟合：通过验证集（Test Set）的强制回测，避免了模型“死记硬背”历史数据。
总结： 这套逻辑就像是一个“全自动的选品算法经理”，每周不知疲倦地为几千个 SPU 进行数千次模拟测算，只为给业务端提供一个最靠谱的数字。
