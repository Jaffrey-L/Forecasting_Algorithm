# 前端设计签字版（M1 / 2026-03-20）

## 定稿状态
- 状态：已定稿（Approved）
- 定稿日期：2026-03-20
- 定稿依据页面：`/design-review`（`frontend/design_review.html`）
- 执行约束：后续前端实现以本签字版与定稿评审页为唯一视觉与结构基线，不再引入 PM 区块到主执行页。

## 1. 目标
在 M1 阶段，将前端统一为“欧美大品牌风格、简洁、极简配色”，并确保主链路满足：
选择 SPU -> 启动任务 -> 查看状态与结果。

## 2. 范围
做什么：
- 重塑 `/` 首页为任务执行主战场（主链路优先）。
- 重塑 `/pm` 页面为项目管理决策页（门禁优先）。
- 统一两页视觉系统（字体、颜色、间距、状态色、按钮层级）。
- 补齐空态、错误态、加载态。

不做什么：
- 不在本轮引入复杂图表和高级分析页。
- 不扩展非 MVP 业务能力。
- 不新增与 M1 无关的 UI 模块。

## 3. 设计原则（签字确认）
- 先业务后视觉：先保证闭环可用，再做视觉增强。
- 一屏理解、两步操作：首页必须在首屏可完成主任务。
- 单主行为：每页一个主按钮、一个主路径。
- 极简克制：单主品牌色 + 中性色，禁止多彩抢焦点。
- 可工程化：每个组件状态可实现、可测试、可验收。

## 5. 交互与状态标准
- SPU 选择模式：`all`（默认）/ `manual` / `sql`。
- `manual`：支持换行、空格、逗号输入，自动去重与标准化。
- `sql`：必须仅返回单列 `spu`，否则报错并给出可读提示。
- 状态统一：`idle` / `queued` / `running` / `stopping` / `completed` / `failed`。
- 必须有：空态文案、加载中反馈、失败重试入口。

## 6. 验收口径（设计）
- 首页首屏可在两步内发起任务并得到反馈。
- 颜色系统不超过 1 个主品牌色 + 状态色。
- `/` 与 `/pm` 视觉一致性通过（组件、字重、间距、圆角统一）。
- 错误态、空态、加载态均有明确样式与文案。

## 7. 实施优先级
- P0：首页结构重排 + 设计系统统一 + 主链路状态完善。
- P1：PM 页结构优化 + 摘要优先的信息层级。
- P2：轻量动效与细节润色（不影响主链路）。

## 8. 签字确认项
- 已确认采用“欧美大品牌、极简、克制”视觉方向。
- 已确认本轮优先 M1 闭环，不扩展非 MVP 能力。
- 已确认先完成设计定稿，再推进后续开发任务。
