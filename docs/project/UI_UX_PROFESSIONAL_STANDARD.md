# UI/UX 专业化执行标准（Mendel 专用 v1）

## 1. 定位
在前后端协同项目中，UI/UX 不是装饰层，而是交付质量与开发效率的核心系统。

## 2. 强制路线
- 设计工作默认走专业流程：需求对齐 -> 信息架构 -> 线框 -> 视觉系统 -> 交互细节 -> 可实现规范 -> 验收走查。
- 涉及关键页面改版时，优先使用 Figma MCP 流程获取或产出设计上下文。
- 禁止“边做边猜”的无规范实现，先有设计决策再进入前端开发。

## 3. Mendel 职责升级
- Mendel 对以下结果负责：
  - 设计决策可解释（每个关键选择都能回答“为什么”）。
  - 页面结构与业务目标一致（先任务闭环，后视觉增强）。
  - 设计稿可工程化落地（组件、状态、间距、变量完整）。
  - 设计验收可量化（可读性、可用性、一致性、可维护性）。

## 4. 自由度与边界
- 给予 Mendel 高自由度探索布局和视觉方案。
- 但必须遵守边界：
  - 不偏离当前里程碑目标。
  - 不牺牲可实现性换“视觉炫技”。
  - 不引入破坏一致性的临时样式。

## 5. 交付清单（每次设计迭代必须提供）
- 设计原则（3~5条）
- 信息架构图（区块优先级）
- 视觉系统（字体、颜色、间距、组件变量）
- 状态与异常交互规范
- 前端实现清单（按优先级）
- 风险与取舍说明

## 6. 设计门禁
- 目标对齐门禁：设计是否直接服务当前里程碑目标。
- 可用性门禁：关键路径是否一屏可理解、两步可操作。
- 一致性门禁：组件与状态表达是否统一。
- 工程门禁：前端是否可按规范直接实现，无歧义。
- 复盘门禁：上线后是否沉淀可复用规范。

## 7. 与 PM/前端/测试协作机制
- PM：先确认范围和验收，再启动设计。
- 前端：设计输出必须带实现优先级和组件清单。
- 测试：设计交互状态必须可测，错误态必须可复现。

## 8. 当前项目默认风格约束
- 风格：欧美大品牌风格，克制、简洁、可信赖。
- 色彩：极简中性色 + 单一品牌色，不做多色抢焦点。
- 首屏：主任务优先，信息密度适中，结果摘要可扫读。
