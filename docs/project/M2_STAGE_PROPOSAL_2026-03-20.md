# M2 阶段建议与落地范围（2026-03-20）

## 1. 阶段定位（主人确认口径）
- `smart` 是最终目标模式：稳定、高效、可持续运营。
- `full` 与 `fast` 定位为辅助模式：
  - `full`：用于深度研究、问题复盘、方案验证，不作为日常主模式。
  - `fast`：用于快速试跑、连通性检查、回归冒烟，不作为业务决策主模式。

## 2. M2 总目标（P0）
把 `smart` 打造成默认生产模式，确保在“稳定性、时效、可解释性”三方面同时达标，而非单点追求极限准确率。

## 3. M2 落地任务（已纳入）

### 3.1 Smart 模式强化（P0）
- 固化 smart 模式的算法集合与超参边界，避免频繁漂移。
- 定义 smart 运行门禁：成功率、时长、入库完整性、核心字段完整性。
- 输出 smart 专属运行报告（本次 run 的模型覆盖、失败模型原因、结果摘要）。

### 3.2 `principal_names` 权重预测（P0）
- 数据来源：查询表字段 `principal_names`。
- 新增能力：参考 SKU 权重预测逻辑，构建“负责人权重预测”。
- 强约束：**不改变最终入库表颗粒度**（仍保持 SPU + forecast_target_date 一行），负责人只以 JSON 扩展字段写入。
- 输出形态建议：
  - 负责人权重 JSON（与 SKU 权重并行）
  - 负责人维度的预测拆分结果（用于前端与报表查询）
- 验收要点：
  - 能按 run_id 查询负责人权重结果
  - 与 SPU 总量一致性可校验（拆分后加总回 SPU）
  - 异常负责人（缺失/稀疏）有兜底策略

## 4. 非目标（M2 暂不做）
- 不追求 full 模式全模型“全部最优”。
- 不将 fast 模式作为业务主入口。
- 不在 M2 引入与主链路无关的大规模 UI 重构。

## 5. 建议验收（M2）
- Smart 作为默认运行模式连续通过（建议 3 次）。
- principal_names 权重预测入库并可查询。
- 前端结果摘要可显示负责人维度核心信息（可在后续迭代逐步增强）。
