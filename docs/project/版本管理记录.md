# 版本管理记录

## v1.3.2 (2026-03-31)

### 发布日期
2026-03-31

### 主要功能
1. **环境职责收敛**：明确 `Windows` 作为前端与代码测试环境，`Linux` 作为正式运行与每周自动预测环境。
2. **运行口径统一**：默认预测模式固定为 `smart`，默认预测范围收敛为 `108 周及以上样本周数` 的 SPU。
3. **前端观测定位**：前端页面保留为运行观测台，任务运行中可查看状态、日志、进度，任务完成后持续展示最近一次结果，直到下一次任务启动。
4. **Linux 执行入口统一**：正式环境统一通过 `scripts/run_forecast_job.py` 触发任务，为后续 `systemd timer` 周日自动执行做准备。

### 本次操作记录
- Windows 本地分支完成代码修改与测试，主要涉及：
  - `forecast_dashboard_v2.html`
  - `src/api/app.py`
  - `src/api/runtime.py`
- Linux 服务器完成 Python 虚拟环境创建、依赖安装、`uvicorn` 启动验证。
- Linux 服务器访问地址确认：
  - 前端/API：`http://192.168.1.242:8000`
- Linux 手工执行命令确认：
  - `python -m uvicorn src.api.app:app --host 0.0.0.0 --port 8000`
  - `python scripts/run_forecast_job.py --mode smart --selection-type all --trigger-source manual`
- 运行中发现 `pkg_resources` 缺失，已通过降级 `setuptools` 解决兼容问题。

### 当前阻塞项
1. **数据库权限**：`ai_reader` 账号对 `lx_ods` schema 缺少读取权限，导致预测任务在查数阶段失败。
2. **发布分支治理**：Linux 当前拉取 `master`，而 Windows 改动在开发分支；后续必须固定“Windows 测试 -> GitHub 提交 -> Linux 拉取发布分支”的流程。

### 固定发布流程
1. Windows 本地开发与测试。
2. 在 Windows 完成 `git add / commit / push`。
3. Linux 服务器执行 `git fetch / git checkout <发布分支> / git pull`。
4. Linux 重启正式服务。
5. 手工执行一次预测验收，确认前端可查看运行中状态与完成结果。

### 部署建议
1. **Windows 角色**：仅作为测试与验证环境，不直接作为正式预测执行环境。
2. **Linux 角色**：作为唯一正式环境，负责常驻前端/API 服务与每周日自动预测。
3. **正式服务**：后续切换为 `systemd` 托管，满足开机自启与异常自动重启。
4. **定时策略**：每周日固定触发预测，前端页面持续展示最近一次完成结果，运行期间实时显示执行状态。

## v1.3.1 (2026-03-24)

### 发布日期
2026-03-24

### 主要功能
1. **Prophet模型修复**：将Prophet从多进程执行改为单进程执行，解决Windows多进程兼容性问题
2. **环境变量配置**：在algorithm_engine.py文件开头设置Prophet环境变量，确保stan_backend正确初始化
3. **NumPy版本兼容**：降级NumPy到1.26.4版本，解决与TensorFlow的兼容性问题
4. **错误日志增强**：增强模型失败时的错误日志输出，便于问题诊断

### 修复内容
- **Prophet 'stan_backend'错误**：在config_and_utils.py的_mp_worker函数中设置STAN_BACKEND和CMDSTANPY_COMPILE环境变量
- **Windows多进程编译问题**：将Prophet改为单进程运行，避免多进程环境下每个子进程都尝试编译导致的冲突
- **NumPy 2.0+兼容性**：解决`np.float_`被移除的问题，使用`np.float64`代替
- **TensorFlow兼容性**：升级NumPy到1.26.4，确保与TensorFlow 2.13.0的兼容性

### 测试结论
- API服务成功启动并运行在http://0.0.0.0:8000
- 所有模型（Prophet、XGBoost、LightGBM、SARIMA等）均能正常执行
- 前端页面可以正常访问并与API交互
- 预测结果能正确存储到数据库

### 部署建议
1. **环境配置**：确保NumPy版本为1.26.4，避免使用NumPy 2.0+
2. **运行环境**：在Windows环境下，Prophet将以单进程模式运行；在Linux环境下，可根据需要调整为多进程模式
3. **监控**：定期检查API服务运行状态，确保所有模型正常执行

### 后续计划
1. **生产环境部署**：在Linux生产环境中部署时，可考虑恢复多进程执行以提高性能
2. **模型优化**：持续优化模型参数，提高预测准确性
3. **监控系统**：完善监控系统，及时发现和处理异常情况
